# Outlook 模板邮件工具

这是一个 Windows Java 桌面工具：编辑自己的模板、手动填写变量、自动计算日期，每次生成一封邮件。支持打开 Outlook 编辑，也支持经弹框确认后通过 Microsoft 365 直接发送。

## 1. 启动

1. 将整个压缩包解压到一个文件夹，不要在压缩包内直接启动。
2. 电脑需要有 Java 8 或以上运行环境（建议使用公司 IT 维护的受支持版本）。工具不附带 Java，不需要 Maven 或其他第三方库。
3. 双击 `Start.bat`。如果显示找不到 Java，请让 IT 配置 Java，或者将获准使用的 Windows Java 运行环境放进工具目录的 `runtime` 文件夹，确保存在 `runtime\bin\java.exe`。
4. 初次启动会创建一个“付款提醒”示例模板。进入“编辑模板”，替换成你的实际内容。

也可以在命令行运行 `java -jar OutlookTemplateTool.jar`。

## 2. 不勾选直接发送：打开 Outlook

1. 在 Windows 设置的“应用 → 默认应用”中，把 `MAILTO` 协议设为要使用的 Outlook（经典版或新版）。
2. 在“生成邮件”页面选择模板，双击变量的“填写内容”单元格输入内容。
3. 查看预览，点击“打开 Outlook”。
4. 工具会请求系统打开邮件编辑窗口，填入收件人、主题和正文。请在 Outlook 中检查并发送。

此模式不需要填写应用 ID，也不需要额外登录。打开的是 Windows 默认邮件应用；工具无法代替你决定默认应用，或检测该应用实际登录的账号。

邮件链接存在长度和客户端兼容性限制。为了避免内容被截断，编码后超过本工具 1,800 字符的保守阈值时，会提示“复制完整正文并打开 Outlook”。确认后正文进入剪贴板，Outlook 窗口中带上收件人和主题，你在正文处按 **Ctrl+V** 即可。若收件人和主题本身也超过阈值，工具会拒绝打开并提示缩短。这个阈值是兼容性保护，不是微软公布的统一上限。

## 3. 勾选直接发送：首次 Microsoft 365 配置

此模式直接连接 **Microsoft 365 国际版（Global）**，不依赖本机 Outlook 的版本或是否正在运行。当前版本不支持世纪互联运营的 Microsoft 365 或美国政府云。

除了首次账号授权，还需要一个公司租户内的应用注册。你没有注册权限时，请把以下步骤交给 IT 管理员；不需要提供邮箱密码或客户端密钥。

### 给 IT 的配置步骤

1. 在 [Microsoft Entra 管理中心](https://entra.microsoft.com/) 打开 **应用注册 → 新注册**。
2. 名称可设为“Outlook 模板邮件工具”；支持的账号类型选择 **仅此组织目录中的账号（单租户）**。
3. 在注册后的概述页复制 **应用（客户端）ID** 和 **目录（租户）ID**。
4. 打开 **身份验证 → 添加平台 → 移动和桌面应用程序**，添加自定义重定向 URI：`http://localhost`。必须使用桌面公共客户端平台，不要注册成 Web 或 SPA，也不要创建客户端密钥。
5. 在 **API 权限** 中添加 Microsoft Graph 的以下 **委托权限（Delegated permissions）**：
   - `Mail.Send`：代表登录用户发送邮件。
   - `User.Read`：读取登录账号的基本资料，在发送确认框中显示真实发件邮箱。
   - `offline_access`：允许更新登录状态，减少重复登录。工具在授权请求中请求此范围。
6. 按公司策略完成用户同意或管理员同意，并允许目标用户访问这个应用。不要添加 Application 类型的邮件权限，也不需要 `Mail.Read` 或 `Mail.ReadWrite`。
7. 工具采用系统浏览器登录和授权码 + PKCE，并在随机本地端口接收登录回调。公司设备策略需要允许本机浏览器回到 `localhost`。这不是设备代码登录，不需要为设备代码流程启用开关。

### 工具中的配置步骤

1. 进入“账号与设置”，填入租户 ID、客户端 ID，点击“保存设置”。
2. 点击“登录 Microsoft 365”。浏览器会打开微软登录页面；选择与 Outlook 相同的公司邮箱并完成授权。
3. 返回工具，核对“当前授权账号”。工具不会自动继承或核对 Outlook 的登录会话。
4. 勾选“确认后直接发送”，点击“保存设置”。保存后才生效；这个偏好会在下次启动时保留。
5. 返回“生成邮件”，填写变量，点击“发送…”。
6. 确认框显示实际发件账号、收件人、主题、完整正文。点击“确认发送”才会提交；关闭确认框或点击“取消”均不发送。

工具将邮件保存到发件账号的已发送邮件。界面显示“Microsoft 365 已接受发送请求”表示服务已经接受请求，不保证邮件已送达收件人。工具不会自动加上 Outlook 签名，署名应写进模板。

若公司要求管理员批准、设备合规或额外登录，必须遵守该租户策略；首次授权不意味着以后绝不需要再次登录。

## 4. 模板写法

在“编辑模板”中可以新建、保存、删除模板。名称、收件人、主题、正文都在本地保存。收件人、主题和正文支持占位符；多个收件地址用分号分隔，仍作为同一封邮件发送。

| 类型 | 示例 | 说明 |
|---|---|---|
| 手动变量 | `{{姓名}}`、`{{金额}}`、`{{收件邮箱}}` | 自动出现在填写表格中，同名变量只需填一次 |
| 今天 | `{{今天}}` | 默认输出 `yyyy-MM-dd` |
| 日期格式 | `{{今天:yyyy年M月d日}}` | 例如 2026年9月11日 |
| 日期加减 | `{{今天+7天:yyyy-MM-dd}}` | 今天后 7 个自然日 |
| 前一天 | `{{今天-1天:yyyy-MM-dd}}` | 昨天 |

日期以运行电脑的本地日期为准，在点击生成/发送时统一计算；这意味着跨过午夜后，下一次生成会更新日期。格式遵循 Java DateTimeFormatter，月份用大写 `MM`，年份建议使用小写 `yyyy`。不支持工作日、节假日判断、自定义脚本或任意函数执行。以“今天”开头的占位符保留给日期函数。

金额按手动输入的文本填入，不自动计算或四舍五入。所有变量必须填写，日期函数除外。正文是纯文本，不包含附件、内嵌图片或富文本。

示例主题：

```
{{姓名}} · 付款提醒 · {{今天:yyyy-MM-dd}}
```

示例正文：

```
{{姓名}}，您好：

本次待付金额为 {{金额}} 元，请于 {{今天+7天:yyyy-MM-dd}} 前安排付款。

谢谢！
{{署名}}
```

## 5. 本地数据与登录状态

Windows 数据位置：`%APPDATA%\OutlookTemplateTool`。

- `templates.json`：模板；可以备份，内容为普通文本。
- `settings.properties`：应用 ID、租户 ID、发送偏好，不包含邮箱密码。
- `session.dpapi`：由 Windows DPAPI 使用当前 Windows 用户加密的登录更新令牌。不能简单复制到另一个用户或电脑上使用。
- `app.lock`：避免同时打开多个工具实例；不需要手动删除。

不会持久化你每次手动填写的姓名、金额、收件地址，也不记录正文日志。把真实数据直接写在模板里则会随模板保存。工具不保存邮箱密码，不把令牌写入明文配置。如果 Windows 安全存储不可用，会显示提示并仅在本次运行期间保留登录状态。

“退出并清除本机登录状态”会清除工具的本地凭据，不会注销微软网页登录，也不代表撤销租户内的应用同意。

## 6. 常见问题

**打开了其他邮件软件**：调整 Windows 的 MAILTO 默认应用为 Outlook。

**长邮件正文没有自动填入**：选择长邮件备用操作后，正文在剪贴板中，需要 Ctrl+V 粘贴。

**登录提示重定向地址错误（AADSTS50011）**：检查应用平台是否为“移动和桌面应用程序”，并已注册 `http://localhost`。实际登录地址带随机端口是正常的。

**登录要求密钥（AADSTS7000218）**：确认应用不是按 Web 机密客户端配置；重新核对桌面平台和回调地址。

**需要管理员批准、403 或拒绝访问**：让公司 IT 检查委托权限、应用同意、用户分配、Exchange Online 邮箱及访问策略。工具不会绕过公司策略。

**网络中断或发送超时**：可能已被微软接收。先检查 Outlook“已发送邮件”，再决定是否重发；工具不会自动重试发送，避免重复邮件。

**找不到 Java／启动失败**：运行 `Start.bat` 查看错误；使用公司认可的 Java 运行环境。

**模板文件损坏**：工具会停止启动并保留原文件，使用备份恢复 `templates.json`，不要直接丢弃现有模板。

## 7. 开发与验证记录

源代码在 `src/mailtool`，不依赖第三方库。Windows 有 JDK 时双击 `Build.bat` 重新编译；`Test.bat` 运行模拟测试。测试使用本机回环服务，不连接微软，也不发送真实邮件。

本次在 macOS / OpenJDK 8 环境完成编译和 72 项自动化检查，覆盖模板变量、日期跨月/跨年、中文邮件链接、JSON、文件保存、PKCE、登录回调 state 校验、Graph 模拟发送及错误不自动重试。界面检查验证了三个页面、变量预览与模板保存，另通过模拟发送验证了取消不发送、确认仅发送一次及忙碌时重复点击不重复发送。

尚未实测：Windows 两种 Outlook 的实际唤起、Windows DPAPI、公司租户登录、真实邮件发送。因此这是可交付试用版，需要在目标 Windows 电脑上完成这些环境验证。建议先用自己的邮箱作为收件人，由你在工具内确认发送一封测试邮件。

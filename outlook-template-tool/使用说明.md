# Outlook 模板邮件工具

这是一个 Windows Java 桌面工具：编辑自己的邮件模板、手动填写变量、自动计算日期，每次生成一封邮件。工具直接使用桌面 Outlook 当前配置的账号，不要求在程序中再次登录。

## 1. 启动

1. 将整个工具包解压到一个文件夹，不要在压缩包内直接启动。
2. 电脑需要 Java 8 或以上运行环境，建议使用公司 IT 维护的受支持版本。
3. 双击 `Start.bat`。如果提示找不到 Java，请让 IT 配置 Java；也可以将获准使用的 Windows Java 运行环境放入工具目录的 `runtime` 文件夹，确保存在 `runtime\bin\java.exe`。
4. 初次启动会创建一个“付款提醒”示例模板。进入“编辑模板”修改或新建模板。

也可以在命令行运行 `java -jar OutlookTemplateTool.jar`。

## 2. Outlook 版本支持

| 功能 | 经典 Outlook | 新版 Outlook |
|---|---|---|
| 使用桌面 Outlook 当前账号 | 支持 | 本机接口不支持 |
| 生成并打开邮件窗口 | 直接调用 Outlook | 通过 Windows 默认邮件应用打开 |
| 确认后直接发送 | 支持 | 不支持 |
| 程序内再次登录 | 不需要 | 不需要 |

“打开 Outlook”会先尝试经典 Outlook 本机接口。检测不到时，工具会自动通过 Windows 的默认 `MAILTO` 应用打开邮件；因此使用新版 Outlook 时，需要先在 Windows 设置的“应用 → 默认应用”中，将 `MAILTO` 协议设为新版 Outlook。

如果同时安装经典版和新版，“打开 Outlook”会优先使用经典版。

## 3. 打开可编辑邮件

1. 在“生成邮件”页面选择模板。
2. 双击变量的“填写内容”单元格输入内容。
3. 检查右侧预览，点击“打开 Outlook”。
4. 经典版会直接创建并显示邮件窗口；新版会通过 Windows 默认邮件应用打开。请在 Outlook 中再次检查并发送。

经典 Outlook 本机接口没有邮件链接长度限制。只有退回新版 Outlook 的 `MAILTO` 方式时，才会遇到链接长度和客户端兼容性限制。编码后超过工具采用的 1,800 字符保守阈值时，工具会提示复制完整正文；确认后 Outlook 窗口会带上收件人、抄送人和主题，你需要在正文处按 **Ctrl+V**。该阈值是兼容性保护，不是微软公布的统一上限。

## 4. 确认后直接发送

直接发送仅适用于经典 Outlook：

1. 进入“Outlook 与设置”，点击“检测经典 Outlook”，核对当前账号。
2. 勾选“确认后直接发送”。设置会立即保存。
3. 返回“生成邮件”，填写变量并点击“发送…”。
4. 确认框会显示实际发件账号、收件人、抄送人、主题和完整正文。
5. 点击“确认发送”后，工具调用当前经典 Outlook 账号发送；取消或关闭确认框不会发送。

邮件应进入当前账号的“已发送邮件”。Outlook 或公司的安全策略可能另外显示“某个程序正在尝试发送邮件”等提示。工具不会绕过这些提示或公司策略。

如果检测不到经典 Outlook，直接发送会停止并提示关闭该选项，不会转为其他网络发送方式，也不会要求登录 Microsoft 365。

直接发送不会自动插入 Outlook 签名。请把署名写入模板或使用署名变量。

## 5. 收件人和抄送人

模板包含“收件人”和可选的“抄送人”字段，两处支持相同格式：

```text
Jim zheng<jim_zheng@mail.com>
Jim zheng <jim_zheng@mail.com>
jim_zheng@mail.com
```

多人使用英文分号 `;` 或中文分号 `；` 分隔：

```text
Jim zheng<jim_zheng@mail.com>; Jane Lee<jane_lee@mail.com>
```

显示名称和邮箱中间是否有空格均可。工具会校验邮箱格式，并在预览和经典 Outlook 中保留显示名称。新版 Outlook 的系统邮件链接只传递实际邮箱地址，最终显示名称由新版 Outlook 解析。

收件人和抄送人都可以使用模板变量，例如：

```text
{{客户姓名}}<{{客户邮箱}}>; {{负责人姓名}}<{{负责人邮箱}}>
```

抄送人可以完全留空。相同列表中重复的邮箱会按不区分大小写去重。

## 6. 模板变量和日期

在“编辑模板”中可以新建、保存和删除模板。收件人、抄送人、主题和正文都支持占位符。

| 类型 | 示例 | 说明 |
|---|---|---|
| 手动变量 | `{{姓名}}`、`{{金额}}`、`{{收件邮箱}}` | 自动出现在填写表格中，同名变量只需填一次 |
| 今天 | `{{今天}}` | 默认输出 `yyyy-MM-dd` |
| 日期格式 | `{{今天:yyyy年M月d日}}` | 例如 2026年9月15日 |
| 日期加减 | `{{今天+7天:yyyy-MM-dd}}` | 今天后 7 个自然日 |
| 前一天 | `{{今天-1天:yyyy-MM-dd}}` | 昨天 |

日期以运行电脑的本地日期为准，在点击生成或发送时统一计算。格式遵循 Java DateTimeFormatter，月份使用大写 `MM`，年份建议使用小写 `yyyy`。当前不支持工作日、节假日判断、自定义脚本或任意函数执行。

金额按手动输入的文本填入，不自动计算或四舍五入。除日期函数外，所有变量都必须填写。正文为纯文本，不包含附件、内嵌图片或富文本。

## 7. 本地数据与升级

Windows 数据位置：`%APPDATA%\OutlookTemplateTool`。

- `templates.json`：模板，可以自行备份，内容为普通文本。
- `settings.properties`：只保存“是否直接发送”偏好。
- `app.lock`：避免同时打开多个工具实例。

工具不持久化每次手动填写的姓名、金额、收件地址或抄送地址，也不记录正文日志。把真实数据直接写入模板时，这些内容会随模板保存。

从上一版升级时，旧模板会自动增加空的抄送字段；原模板内容继续保留。工具会删除上一版产生的本地 Microsoft 365 登录令牌，并从设置中移除租户 ID 和应用 ID。

## 8. 常见问题

**打开了其他邮件软件**：Windows 没检测到经典 Outlook 接口并使用了备用方式。请将 `MAILTO` 默认应用设为需要使用的 Outlook。

**直接发送提示不支持**：当前只有新版 Outlook，或经典 Outlook 未正确安装和配置。关闭“确认后直接发送”，使用“打开 Outlook”。

**Outlook 无法解析收件人**：检查邮箱拼写、尖括号是否成对，以及多人之间是否使用分号。

**Outlook 显示程序访问警告**：这是 Outlook 或公司的安全策略。请按公司规定处理，工具不会自动确认该提示。

**发送超时或结果不确定**：先检查 Outlook 的“已发送邮件”，再决定是否重试，避免重复发送。工具不会自动重试。

**找不到 Java或启动失败**：运行 `Start.bat` 查看错误，并使用公司认可的 Java 运行环境。

**模板文件损坏**：工具会停止启动并保留原文件。请使用备份恢复 `templates.json`。

## 9. 开发与验证

源代码在 `src/mailtool`，不依赖第三方库。Windows 有 JDK 时运行 `Build.bat` 重新编译；`Test.bat` 运行模拟测试，不打开或发送真实邮件。

当前版本在 OpenJDK 8 环境完成编译和自动化检查，覆盖旧模板升级、抄送保存、显示名称地址、多人列表、中文邮件链接、日期跨月/跨年、Outlook 指令内容，以及失败后不自动重试。

尚未在目标 Windows 电脑上实测经典 Outlook 本机调用、新版 Outlook 实际唤起和真实发送。首次使用时，建议先以自己的邮箱作为收件人，分别测试“打开 Outlook”和“确认后直接发送”。
